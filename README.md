# ✈️ Aviation Pro: 智能航司专注调度系统 (Flight Concentrator)

## 📖 项目简介
### 1.1 设计初衷：打破传统专注力工具的瓶颈
在当下信息碎片化的时代，大众的深度专注能力持续被稀释，番茄工作法作为经典的时间管理工具，被广泛应用于各类专注力应用中。但绝大多数同类产品都停留在“基础倒计时+统计报表”的单调模式中，交互枯燥、反馈滞后、长期使用动力不足是用户普遍的痛点——很多人下载后仅使用数次便因缺乏正反馈而放弃，无法真正形成长期专注的习惯。

Aviation Pro 正是针对这一痛点诞生的产品。我们跳出了“工具类应用”的固化思维，以“游戏化沉浸”为核心设计理念，将枯燥的专注行为包装成极具仪式感与成就感的航空运营体验，让用户在完成现实任务的过程中，同步获得模拟经营类游戏的成长乐趣，用正向激励驱动用户主动保持专注，真正实现“在娱乐中提升效率”。

### 1.2 核心定位：游戏化沉浸式专注管理平台
Aviation Pro 是一款基于 HarmonyOS 全场景生态、采用 ArkTS 语言原生开发的专注力管理应用。它以“民航运营”为核心主题，将用户的每一次专注行为转化为一次完整的航班执飞过程，用户将以“航司网络机长”的身份，从零开始经营属于自己的航空公司。

与市面上简单换皮的游戏化番茄钟不同，本项目构建了完整的商业闭环与成长体系：用户通过完成阅读、编程、学习、工作等现实专注任务积攒飞行里程与虚拟资金，逐步解锁全国真实地理坐标的机场航线，购买并扩充涵盖空客、波音、商飞三大制造商的客机车队，最终搭建起覆盖全国的航线网络，打造属于自己的航空帝国。整个成长路径与用户的专注行为深度绑定，每一分钟的专注都能转化为可视化的成长成果。

### 1.3 核心玩法概览
应用的核心玩法围绕“航班执飞”展开，完整流程如下：
1. **航线规划**：用户创建专注任务时，相当于提交一份航班计划，可自定义任务名称、专注时长，选择出发与到达机场，也可交由系统自动匹配最优航线。
2. **航班执飞**：开启专注后进入驾驶舱界面，倒计时同步对应航班飞行过程，期间界面会模拟真实飞行的高度、速度变化，提供沉浸式视觉反馈。若中途退出应用，航班将触发“颠簸”惩罚，降低最终收益。
3. **落地结算**：专注时长结束后航班顺利落地，系统自动结算本次飞行获得的虚拟资金、飞行里程，并更新用户的运营数据。
4. **运营扩张**：积累的资金可用于购买新的客机机型、开通更多城市的机场通航权，逐步扩大航司规模，解锁更高级的航线与更高的收益倍率。
5. **联机协作**：用户可添加好友并开启“代码共享航班”，多人共同执行同一个大航班任务，互相监督专注进度，共享飞行收益。

### 1.4 目标用户与使用场景
本应用的核心目标用户覆盖学生群体、职场办公人群以及模拟经营类游戏爱好者：
- **学生用户**：可用于自习、背书、刷题等学习场景，将学习时长转化为航司成长动力，缓解学习的枯燥感。
- **职场用户**：适用于深度工作、项目攻坚、文档撰写等场景，通过航班调度规划每日工作节奏，提升工作效率。
- **航空与模拟经营爱好者**：真实的机型图鉴与地理航线网络具备收藏与探索乐趣，满足爱好者的收集欲与经营成就感。

同时，得益于 HarmonyOS 的多设备特性，应用可适配手机、平板、折叠屏等多种设备，覆盖通勤、居家、图书馆、办公室等多场景使用需求。

## ✨ 核心技术亮点 (Core Highlights)
### 3.1 响应式多屏适配 (Responsive UI)
#### 3.1.1 技术选型：ArkUI 栅格系统与断点能力
本项目深度基于 ArkUI 声明式UI框架，采用 `GridRow` / `GridCol` 栅格布局组件搭配 `.lanes()` 断点系统实现响应式适配，摒弃了传统多端适配中“多套布局代码”的冗余方案，实现一套代码同时适配手机直屏、折叠屏展开态、平板等多种设备尺寸。

系统内置了 3 个核心断点：
- 窄屏断点（< 600vp）：对应手机竖屏场景，采用单列布局，所有模块纵向排列，优先保证信息可读性。
- 中屏断点（600vp - 1200vp）：对应折叠屏展开、小尺寸平板场景，采用双列布局，左侧为导航与列表区，右侧为详情展示区。
- 宽屏断点（> 1200vp）：对应大尺寸平板场景，采用三列瀑布流布局，同时展示调度列表、飞行详情、航线地图三个模块，提升大屏信息密度。

#### 3.1.2 多终端布局适配逻辑
不同设备下，应用的界面结构会自动重组，但核心业务逻辑完全一致：
- **手机端**：采用底部 Tab 导航，航班调度、驾驶舱、地图、商店、个人中心依次排列，通过左右滑动或点击切换页面，适配单手操作习惯。
- **折叠屏/平板端**：采用左侧导航栏 + 右侧内容区的双栏结构，调度列表与航班详情左右分屏展示，地图模块可全屏扩展，充分利用大屏空间，减少页面跳转次数，提升操作效率。

当用户展开/折叠折叠屏、旋转设备屏幕时，界面会在对应断点间无缝切换，当前正在操作的航班信息、输入内容、飞行进度会完整保留，不会因布局变化丢失状态。

#### 3.1.3 无缝状态保持与布局重组
为了实现流畅的布局切换，项目采用了“状态驱动UI”的设计思路：所有业务数据与页面状态与布局组件解耦，当屏幕尺寸变化触发断点切换时，仅重新渲染布局结构，底层的航班数据、用户进度、表单输入内容全部保留，用户感知不到任何断层，实现真正的“无缝重组”。

### 3.2 跨设备自由流转 (Continuation)
#### 3.2.1 分布式能力底层原理
跨设备自由流转能力深度接入 HarmonyOS 分布式软总线技术，依托系统底层的分布式能力底座，实现应用在同局域网内的多设备间无缝接续。其核心原理是将当前应用的页面栈、业务状态、用户操作进度进行序列化打包，通过分布式软总线传输至目标设备，目标设备接收后直接恢复应用状态与页面层级，实现“一端配置，多端接续”。

#### 3.2.2 流转触发与接续流程
用户可在应用的任意界面点击右上角的“流转”按钮，系统会自动搜索同局域网内登录同一华为账号的 HarmonyOS 设备。选择目标设备后，当前应用会在原设备上关闭，同时在目标设备上自动启动并恢复到完全一致的界面与状态。

典型使用场景：用户在通勤路上用手机规划好了当日的全部航班航线，回到家后可一键将应用流转至平板上，平板直接进入待飞状态，用户可直接在大屏上开启专注飞行，无需重复设置航线与机型，整个流转过程耗时不超过 2 秒。

#### 3.2.3 业务场景与用户价值
跨设备流转能力打破了单设备的使用限制，让专注行为可以适配不同场景的设备需求：外出时用手机轻量化操作，居家学习时用平板获得沉浸式驾驶舱体验，办公时用电脑端（后续迭代）同步日程。应用状态随用户场景自然流转，真正实现了 HarmonyOS 全场景智慧体验的设计理念。

### 3.3 分布式数据协同 (Distributed Data Object)
#### 3.3.1 ArkData 分布式数据对象机制
项目基于 `@kit.ArkData` 中的分布式数据对象（Distributed Data Object）能力，构建了多端内存数据同步通道。核心业务数据（用户资金、机队库、航线进度、任务列表）被封装为分布式数据对象，当同一账号下的多台设备同时运行应用时，任意一端的数据变更都会实时同步到其他设备。

与传统云端同步不同，分布式数据对象的同步是基于局域网内存级的同步，同步延迟低于 100ms，且无需经过云端服务器，数据仅在用户自有设备间传输，具备极高的隐私性与实时性。

#### 3.3.2 多端实时同步策略
系统对不同类型的数据采用了差异化的同步策略：
- **强实时数据**（如飞行进度、在线状态）：采用增量实时同步，每秒同步一次状态，保证多端看到的飞行进度完全一致。
- **基础数据**（如资金、机队、已解锁机场）：采用变更触发同步，仅当数据发生变化时才触发同步，降低设备功耗与网络开销。

同时系统内置了冲突解决机制，当多端同时修改同一数据时，以最新操作时间的数据为准，避免出现数据不一致的问题。

#### 3.3.3 连接状态可视化设计
为了让用户直观感知分布式协同状态，应用在个人中心界面设计了“多设备连接指示灯”模块，以卡片形式展示当前同账号下的在线设备列表，设备图标旁的指示灯会实时显示连接状态：绿色代表已连接且数据同步正常，灰色代表设备离线，黄色代表同步中。用户可直观看到自己的哪些设备正在同步数据，清晰感知分布式能力的运行状态。

### 3.4 纯本地多段连飞推演算法 (Local AI Routing)
#### 3.4.1 算法设计目标与优势
多段连飞是本应用的高级功能，允许用户一次性设置多个连续的专注任务，系统自动串联成一条多段中转的航线。为了保护用户隐私、保证无网络环境下也能正常使用，项目没有采用云端路由接口，而是设计了纯本地运行的独立推演引擎，所有计算全部在设备本地完成。

该算法的核心优势在于：
- **零网络依赖**：离线环境下可正常使用，不受网络信号限制。
- **隐私保护**：用户的任务内容、时间安排全部存储在本地，不会上传至任何服务器。
- **极速响应**：本地计算延迟远低于云端请求，输入任务后毫秒级即可生成航线方案。

#### 3.4.2 航线生成核心逻辑
算法的输入为用户设置的多段任务时长列表与已解锁机场集合，输出为最优的起降机场序列，核心逻辑包含三个步骤：
1. **时长匹配距离**：根据每段任务的时长，结合机型巡航速度，换算出对应的理论飞行距离，圈定可选的机场范围。
2. **路径去闭环**：采用贪心算法结合回溯校验，自动排除环线与回头航线，保证整条航线为单向递进的连贯路径，不会出现重复起降的机场。
3. **收益最优排序**：在所有可行路径中，选择总收益最高的机场组合作为最终方案，同时兼顾航线的地理合理性。

#### 3.4.3 机型匹配与收益优化
生成机场序列后，算法会自动为每一段航线匹配最合适的执飞机型：根据航线距离匹配对应续航的机型，在续航满足的前提下，优先选择收益系数更高的机型，保证单次多段连飞的总收益最大化。用户也可手动修改每段的执飞机型，算法会实时校验机型续航是否满足航线距离，不满足时给出提示。

#### 3.4.4 本地运行的可靠性价值
纯本地算法的设计，让应用在地铁、图书馆、地下室等无网络场景下依然可以完整使用全部核心功能，避免了同类应用“无网就无法规划任务”的痛点。同时所有任务数据本地化的设计，也打消了用户对于“日程隐私泄露”的顾虑，提升了产品的信任感。

## 🚀 主要功能模块 (Features)
### 4.1 航班调度引擎
#### 4.1.1 任务-航线映射机制
航班调度引擎是整个应用的核心业务中枢，负责将用户的现实专注任务转化为可视化的航班计划。引擎建立了完整的映射规则：任务时长对应飞行距离，任务类型对应航班属性（学习任务对应客运航班、工作任务对应货运航班），任务难度对应收益倍率。

用户创建任务时，既可以手动选择出发机场、到达机场与执飞机型，也可以只输入时长与任务名称，由引擎自动匹配最优航线与机型，兼顾自定义自由度与便捷性。

#### 4.1.2 多段航班编排能力
调度引擎支持单段航班与多段连飞两种模式。单段模式对应单个专注任务，多段模式则支持用户一次性添加 2-6 个连续任务，引擎自动串联成一条中转航线，适合规划半天或一整天的专注日程。

多段航班支持设置中转休息时间，对应航班的机场经停时长，休息结束后自动开启下一段飞行，帮助用户科学规划专注与休息的节奏，符合番茄工作法的科学原理。

#### 4.1.3 日程可视化与复盘
调度主界面采用“航班时刻表”式的设计，以时间轴形式展示当日所有航班，清晰标注待飞、飞行中、已完成三种状态，用户可直观看到自己一天的时间安排，就像航司调度员一样掌控全局。

每日结束后，调度引擎会生成当日运营日报，统计总飞行时长、完成航班数、总里程、总收益、完成率等数据，并以柱状图展示近 7 天的专注趋势，帮助用户复盘时间管理效果，调整后续规划。

### 4.2 Web GIS 航线拓扑系统
#### 4.2.1 ArkWeb 与高德地图双向通信架构
航线拓扑系统基于 `ArkWeb` 组件与高德地图 Web API 联合实现。ArkWeb 作为原生与 Web 的桥梁，承担了双向通信的角色：
- **原生向 Web 传值**：ArkTS 侧将航班的起止机场经纬度、航班状态、机型信息通过 `postMessage` 接口传递给 Web 页面，Web 端接收后调用高德地图 API 进行绘制。
- **Web 向原生回调**：用户在地图上点击机场、缩放拖拽等操作，Web 端会将操作事件与对应数据回传给 ArkTS 侧，原生侧响应并更新业务状态。

这种混合开发架构，既利用了高德地图 Web API 成熟的地图渲染与地理计算能力，又保留了原生应用的流畅交互与业务性能，实现了效果与效率的平衡。

#### 4.2.2 真实地理航迹绘制
系统内所有机场均采用高德地图的真实地理坐标，航班执飞过程中，地图上会实时绘制飞机的移动轨迹，航迹线采用渐变发光效果，已飞过的路段高亮显示，未飞路段为虚线状态。

多段航班会在地图上呈现完整的折线航线，每个中转机场都有明确的标记。随着用户完成越来越多的航班，地图上会逐渐形成覆盖全国的航线拓扑网络，直观展示用户的“航空帝国”版图，带来极强的成就感与收集乐趣。

#### 4.2.3 结算动效与数据可视化
航班完成落地时，地图界面会播放专属结算动效：航迹线逐段点亮，机场图标放大闪烁，同时弹出收益数据卡片，资金、里程数字滚动增长，配合轻微的震动反馈，给用户带来强烈的正向激励。

在航线总览界面，用户可以切换不同的统计维度，查看按省份、按机场等级、按机型分类的航线覆盖数据，支持缩放、拖拽、点击查看详情，具备完整的地理数据可视化能力。

### 4.3 Codeshare 共享航班联机系统
#### 4.3.1 代码共享机制设计
共享航班功能模拟了真实民航业的“代码共享（Codeshare）”合作模式，允许多个用户共同执飞同一个航班任务。该功能的设计初衷是通过社交监督提升用户的专注执行力，解决独自专注时容易懈怠、中途放弃的问题。

每个共享航班有一个唯一的航班编号，创建者为“主承运航司”，加入者为“共享合作航司”，所有参与者使用相同的专注时长，共同完成航班执飞。

#### 4.3.2 好友社交与联机流程
用户可以通过输入对方的 UID 搜索并添加好友，也可以通过航班号直接加入他人的共享航班。好友列表会实时显示对方的在线状态、当前执飞航班与机队规模。

联机流程简单清晰：
1. 一方创建共享航班，设置专注时长与机型，生成航班号。
2. 将航班号分享给好友，好友输入航班号加入。
3. 所有人准备就绪后，由创建者发起起飞，所有设备同步进入倒计时。
4. 飞行过程中可查看每位队友的剩余进度与在线状态。
5. 所有人都完成专注后，航班正式结算，全员获得收益。

#### 4.3.3 互助监督与收益规则
共享航班设计了完善的监督与激励规则：
- 若有人中途退出应用超过 30 秒，全队会收到“航班颠簸”提示，该成员的收益会被扣除，同时影响全队的总收益倍率。
- 若全员都全程专注完成航班，可获得“完美执飞”加成，全队收益提升 20%。
- 参与人数越多，基础收益倍率越高，最高可获得 50% 的额外收益加成。

这种互助监督的机制，让专注从个人行为变成了团队目标，有效提升了用户的坚持动力。

### 4.4 动态沉浸式驾驶舱
#### 4.4.1 玻璃拟态视觉设计语言
驾驶舱界面采用了当下流行的深空玻璃拟态（Glassmorphism）设计风格，以深邃的夜空渐变作为背景，所有数据面板采用半透明磨砂玻璃效果，搭配细微的边框高光与阴影，模拟真实飞机驾驶舱的仪表盘质感，营造出强烈的科技感与沉浸感。

界面元素的排版参考了真实民航驾驶舱的布局逻辑：顶部为飞行状态信息，中部为核心进度区域，底部为辅助功能按钮，既保证了视觉还原度，又兼顾了移动端的操作便捷性。

#### 4.4.2 飞行状态动态模拟
飞行过程中，驾驶舱会模拟真实航班的全阶段状态变化：
- **起飞阶段**：高度与速度数值持续上升，背景的天空颜色从地面视角逐渐过渡到高空深蓝色，模拟爬升过程。
- **巡航阶段**：高度与速度保持稳定，背景缓慢移动的云层与星空，营造平稳飞行的氛围。
- **降落阶段**：高度与速度逐渐下降，天空颜色从高空色过渡到地面视角，对应专注即将结束。

所有数值变化与专注进度严格对应，让用户直观感受到“时间在转化为飞行距离”，强化代入感。

#### 4.4.3 专注过程的正向反馈
驾驶舱界面设计了多处正向反馈细节，帮助用户在专注过程中保持动力：每专注满 5 分钟，界面会触发一次“平流层平稳”提示，伴随轻微的光效反馈；当完成一半进度时，会弹出“航程过半”里程碑提示；临近结束时，会有“即将降落”的预告提示。

同时，界面支持“专注模式”，开启后会隐藏所有非必要按钮，仅保留进度显示，避免信息干扰，帮助用户保持专注状态。

### 4.5 航空商店与经济系统
#### 4.5.1 全国机场通航权体系
航空商店中的机场板块收录了全国 55 个真实民航机场，覆盖国内所有省会城市与重点旅游城市，按照吞吐量分为三个等级：
- **枢纽机场**（10 个）：如北京首都、上海浦东、广州白云等，价格高，通航后可获得更高的航线收益倍率。
- **干线机场**（20 个）：如杭州萧山、成都天府、武汉天河等，性价比适中，是航线网络的骨干节点。
- **支线机场**（25 个）：如丽江三义、敦煌莫高、延吉朝阳川等，价格低廉，适合填充航线网络，解锁成就。

每个机场都配有真实的机场介绍、IATA 代码与航站楼信息，具备真实的科普价值。

#### 4.5.2 三大厂商客机图鉴
机型商店涵盖空客、波音、中国商飞三大民用飞机制造商的 30+ 款经典客机，从支线客机到大型宽体机全覆盖，包括 C919、ARJ21 等国产机型，支持用户打造全国产机队。

每款机型都配有详细的参数卡片，包含真实的载客量、巡航速度、最大航程、首飞时间等数据，同时配有高精度机型图鉴。不同机型具备不同的收益系数与续航限制，长途航线需要对应航程的机型才能执飞，引导用户合理搭配机队结构。

#### 4.5.3 经济循环与成长路径
整个经济系统形成了完整的正向循环：**专注执飞 → 获得资金 → 购买机型/开通机场 → 获得更高收益 → 解锁更高级内容**。这个循环将用户的专注行为与成长感深度绑定，每一次专注都能带来实实在在的运营进展，持续激励用户保持专注习惯。

同时系统还设计了成就系统，包括“百小时机长”“全国航线网络”“全机队收藏家”等数十个成就，解锁成就可获得额外资金与专属徽章，进一步丰富成长路径。

### 5.1 开发与运行环境要求
#### 5.1.1 开发工具与SDK版本

- **调试设备**：支持 HarmonyOS 4.0 及以上系统的手机、平板或折叠屏设备，推荐使用平板或折叠屏设备，以完整体验多屏适配与分布式特性。

- **网络要求**：应用核心功能可离线运行，但 Web GIS 地图模块需要网络环境以加载高德地图资源，建议保持网络通畅以获得完整体验。
- **系统权限**：应用需获取网络权限、分布式数据同步权限、震动反馈权限，首次运行时会弹窗申请，授予对应权限即可正常使用。

#### 5.2.1 项目获取与导入

### 5.3 常见问题与排查方案
1. **工程同步失败**：检查本地 SDK 版本是否匹配，网络是否正常，若缺少对应 SDK 包，可通过 SDK Manager 下载安装。
2. **地图加载空白**：检查设备网络是否通畅，确认高德地图 Web API 可正常访问，若为模拟器环境，需开启模拟器的网络连接。
3. **分布式功能不可用**：确认多台设备连接同一局域网，登录同一华为账号，且均开启了分布式相关权限。
4. **运行卡顿**：建议关闭后台其他应用，若为模拟器可适当分配更高的运行内存，真机上关闭省电模式可获得更流畅的动画效果。
